# Проект домашней работы для Skypro

## Разработка банковского приложения

На данный момент реализованы следующие модули:

1. **Masks**. Маскирует номера и счета банковских карт в следующих форматах:
- Для счетов: **Счет** **4305**.
- Для карт: **Visa Platinum** 7000 79** **** 6361.
- **Функции**:
- `get_mask_card_number`: маскирует номер карты.
- `get_mask_account`: маскирует номер банковского счета.

2. **Widget**. Здесь реализовано две функции:
- `mask_account_card`: принимает карту или счет, анализирует, что это, и использует функции из Masks для скрытия.
- `get_date`: принимает дату и время в нестандартном формате и возвращает в классическом.

3. **Processing**. Здесь реализовано две функции:
- `filter_by_state`: сортирует записи по содержимому ключа, по умолчанию 'EXECUTED', можно менять для сортировки по другому значению.
- `sort_by_date`: сортирует записи по дате, можно менять порядок сортировки, изначально стоит по убыванию.

4. **Generators**. В этом модуле реализованы функции для работы с транзакциями:
- **Функции**:
- `filter_by_currency`: принимает на вход список словарей, представляющих транзакции, и возвращает генератор транзакций, соответствующих указанному коду валюты.
- `transaction_descriptions`: генератор, который возвращает описание каждой транзакции по очереди.
- `card_number_generator`: генератор номеров банковских карт.

5. **Decorators**. Модуль содержит декоратор для логирования выполнения функций:
- **Декоратор**: `log`
- Автоматически логирует начало и конец выполнения функций, а также их результаты или возникающие ошибки.
- Принимает опциональный аргумент `filename` для записи логов в файл. Если `filename` не указан, логи выводятся в консоль.

6. **Transaction Processing**. Новый модуль для обработки транзакций:
- **Функции**:
- `search_transactions`: принимает на вход список транзакций и строку для поиска, возвращает список транзакций, соответствующих описанию с использованием регулярных выражений.
- `count_categories`: принимает на вход список транзакций и возвращает словарь с подсчетом количества операций по категориям.
### Тестирование

Для всех модулей были созданы тесты, которые проверяют корректность работы функций. В тестировании охвачены:

- **Masks**:
  - Проверка правильности маскирования карт и счетов.
  - Обработка различных сценариев, включая пустые и недопустимые значения.

- **Widget**:
  - Проверка правильности работы функции `mask_account_card`, определяющей тип введенных данных и форматирующей даты; результаты тестов охватывают как корректные, так и некорректные входные данные.
  - Проверка функции `get_date`, которая обрабатывает нестандартные форматы дат и выбрасывает исключение для некорректных форматов.

- **Processing**:
  - Проверка корректности фильтрации записей по состоянию и тестирование различных сценариев.
  - Проверка корректности сортировки записей по дате в обоих направлениях (возрастания и убывания).

- **Generators**:
- **filter_by_currency**: Проверка корректности фильтрации транзакций по валюте. Тесты охватывают:
  - Корректное возвращение транзакций для валюты "USD" и "EUR".
  - Проверку на пустой список транзакций, результатом которого должен быть пустой список.
  - Тестирование валюты, для которой нет соответствующих транзакций (например, "JPY"), ожидаемое возвращаемое значение — пустой список.

- **transaction_descriptions**: Проверка корректности генерации описаний транзакций. Тесты включают:
  - Проверку возвращаемого описания для разных индексов транзакций, где для некоторых транзакций указано описание, а для других — "Нет описания", если описание отсутствует (например, для "CANCELED" транзакций).

- **card_number_generator**: Проверка корректности генерации номеров банковских карт. Тесты охватывают:
  - Генерацию последовательных номеров карт в заданном диапазоне.
  - Генерацию одного номера карты при нулевом диапазоне.
  - Проверку, что при попытке сгенерировать карты в обратном диапазоне (например, от 1 до 0) возвращается пустой список.

- **Decorators**:
- **log**: Тестирование декоратора для логирования выполнения функций. Тесты проверяют:
  - Корректное выполнение функции без ошибок и логирование результатов:
  - Проверка на успешном выполнении функции и запись данных в вывод.
  - Обработку ошибок и логирование возникающих исключений:
  - Проверка генерации ошибки (например, деление на ноль) и запись информации об ошибке в вывод.

- **Transaction Processing**:
  - search_transactions: тестирование функции поиска транзакций по описанию:
  - Проверка на отсутствие совпадений с несуществующей строкой.
  - count_categories: тестирование функции подсчета операций по категориям:
  - Проверка обработки пустого списка транзакций.
  - Проверка подсчета количества операций по категориям с несколькими типами операций.
  - Проверка работы с неожиданными описаниями операций.

# Описание модуля main.py

Модуль <code>main.py</code> является основным компонентом приложения, отвечающим за взаимодействие с пользователем и обработку банковских транзакций. Ниже приведены ключевые функции и особенности данного модуля:

1. <strong>Импорт необходимых модулей</strong>:
   - <code>read_csv_transactions</code> и <code>read_excel_transactions</code> для чтения транзакций из файлов CSV и XLSX.
   - <code>log</code> — декоратор для логирования выполнения функций.
   - Функции для работы с маскировкой данных, обработки и фильтрации транзакций.

2. <strong>Функция <code>main</code></strong>:
   - Запускает интерактивное приветствие и предлагает пользователю выбрать способ загрузки транзакций: из файла JSON, CSV или XLSX.
   - В зависимости от выбора пользователя загружает транзакции из соответствующего файла, используя <code>load_transactions</code>, <code>read_csv_transactions</code> или <code>read_excel_transactions</code>.

3. <strong>Фильтрация по статусу</strong>:
   - После загрузки транзакций приложение запрашивает у пользователя статус для фильтрации. Поддерживаются статусы: <code>EXECUTED</code>, <code>CANCELED</code>, <code>PENDING</code>.
   - Запрос повторяется до тех пор, пока пользователь не введет допустимый статус.

4. <strong>Фильтрация транзакций</strong>:
   - Генерация списка отфильтрованных транзакций с учетом статуса, указанного пользователем, с помощью функции <code>filter_by_state</code>.

5. <strong>Сортировка транзакций по дате</strong>:
   - Приложение предлагает пользователю выбрать, хочет ли он отсортировать транзакции по дате. Если пользователь соглашается, он может указать порядок сортировки: по возрастанию или по убыванию. Для этого используется функция <code>sort_by_date</code>.

6. <strong>Фильтрация по валюте</strong>:
   - Приложение предлагает пользователю возможность отфильтровать транзакции по валюте, предлагая вывести только рублевые транзакции (RUB).

7. <strong>Поиск по описанию</strong>:
   - Пользователь может выбрать опцию поиска по определенному слову в описании транзакций. Если он выберет "Да", приложение запросит строку для поиска и применит функцию <code>search_transactions</code> к отфильтрованному списку.

8. <strong>Вывод итогового списка транзакций</strong>:
   - После всех фильтраций приложение выводит итоговый список транзакций, показывая дату, описание, сумму и валюту каждой транзакции.
   - Если транзакции содержат поля "from" и "to", то номера счетов и карт маскируются с помощью функций <code>get_mask_account</code> и <code>get_mask_card_number</code>, чтобы обеспечить безопасность данных.

9. <strong>Проверка наличия транзакций</strong>:
   - Если после всех фильтраций не осталось транзакций, приложение уведомляет пользователя об отсутствии подходящих записей.

Таким образом, модуль <code>main.py</code> обеспечивает удобный интерфейс для работы с банковскими транзакциями, реализуя функционал загрузки, фильтрации и сортировки данных, а также ведя логирование операций пользователя.
